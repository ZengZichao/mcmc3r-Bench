## Languages

- English (`en`): source language for UI keys.
- Simplified Chinese (`zh-CN`): full translation.
- Unknown browser languages fall back to English.
- `?lang=zh` or `?lang=en` overrides stored preference on first load.
- Preference is stored in `localStorage` under `mcmc3r-bench-lang`.

## Files

- `i18n/translations.csv`: the single source of UI strings, columns `key,en,zh`.
- `www/js/i18n.js`: generated dictionary for client-side switching.
- `i18n/help_en.md`, `i18n/help_zh.md`: in-app Help pages.

Never edit `www/js/i18n.js` by hand. Run `Rscript dev/build_i18n.R` after changing
the CSV, and run `Rscript dev/i18n_check.R` before committing.

## Key naming

```
<area>.<component>.<element>[.<variant>]
```

Areas: `app`, `nav`, `common`, `theme`, `cal`, `mcmc`, `ml`, `help`, `about`,
`err`, `hint`, `unit`, `meta`, `plot`, `toast`, `dt`, `footer`.

Rules:

- Keys are stable; English sentences are never keys.
- One key per meaning; reuse instead of duplicating.
- Error keys are `err.<CODE>`; hint keys are `hint.<CODE>`.
- Placeholders use named braces: `{n}`, `{name}`. Values must be named.
- Do not put HTML in translation values.
- Do not translate parameter names, function names, file names, method names,
  software names, units, or citations.

## How switching works

The UI is built once with `data-i18n` attributes. The client stores a dictionary
generated from the CSV. On switch:

1. The dictionary updates every `[data-i18n]` element's text.
2. `[data-i18n-placeholder]`, `[data-i18n-title]`, and
   `[data-i18n-aria-label]` are updated.
3. `<html lang>` changes to `zh-CN` or `en`.
4. The client sends `Shiny.setInputValue("lang", value)`.
5. The server updates `lang`, refreshes server-rendered help, tables, plots,
   errors, and select/radio choice labels.
6. Inputs, uploaded data, and results remain in memory.

Server-side text uses `tr(key, lang, ...)`. UI code uses `tr_span(key, lang)` so
the initial render and subsequent client switches agree.

## Translation workflow

1. Add the English value to the CSV.
2. Translate into Chinese; no empty values.
3. Run `dev/build_i18n.R` and `dev/i18n_check.R`.
4. Update the glossary if a new term is introduced.
5. Request domain review for methods, errors, privacy, licence, and citation
   strings.
6. Include the key list in the pull request description.

## Formatting rules

- Numbers use `.` as the decimal separator; scientific notation is `1.2e-3`.
- Units are separated by a space: `10 Ma`.
- Dates in filenames use UTC `YYYYMMDD-HHMMSS`.
- Chinese headings do not end with a period; English headings use title case.
- Error text: Chinese uses “请…”, English uses “Please…”; avoid blaming language.
- Do not machine-translate high-risk copy without review.

## Validation

`dev/i18n_check.R` checks:

- CSV columns, unique keys, non-empty values.
- Every `err.*` and `hint.*` for the documented error codes.
- Every `tr("...")` key used in `R/`.
- The browser dictionary contains every key.
- No placeholder mismatch between English and Chinese (same named placeholders).

`tests/testthat/test-fct-i18n.R` repeats key checks in the unit suite.

## Adding a language

1. Add a column (or a new table) and update `normalize_lang()`.
2. Extend the client dictionary builder and `lang` choices.
3. Translate help pages and documentation trees.
4. Add the language to the QA matrix and screenshot folders.
5. Do not ship a partially translated language; fall back to English until
   complete.

## Fonts

The UI uses system fonts. Plots use the bundled Noto Sans SC via `sysfonts` and
`showtext`, so Chinese renders on Linux servers without system CJK fonts. Keep
`www/fonts/NotoSansSC-Regular.ttf` and `www/fonts/OFL.txt` together. If the font
is subset, regenerate it from the current translations and documentation, and
retest PNG/PDF exports.
