## 语言

- English（`en`）：界面 key 的源语言。
- 简体中文（`zh-CN`）：完整翻译。
- 未知浏览器语言回退到英文。
- 首次加载时，`?lang=zh` 或 `?lang=en` 覆盖已保存偏好。
- 偏好保存在 `localStorage` 的 `mcmc3r-bench-lang`。

## 文件

- `i18n/translations.csv`：界面文案唯一来源，列为 `key,en,zh`。
- `www/js/i18n.js`：供客户端切换使用的生成字典。
- `i18n/help_en.md`、`i18n/help_zh.md`：应用内帮助页。

不要手工编辑 `www/js/i18n.js`。修改 CSV 后运行 `Rscript dev/build_i18n.R`，提交前运行
`Rscript dev/i18n_check.R`。

## Key 命名

```
<area>.<component>.<element>[.<variant>]
```

区域：`app`、`nav`、`common`、`theme`、`cal`、`mcmc`、`ml`、`help`、`about`、
`err`、`hint`、`unit`、`meta`、`plot`、`toast`、`dt`、`footer`。

规则：

- key 保持稳定；绝不使用英文句子作为 key。
- 一个含义一个 key；优先复用而非重复。
- 错误 key 为 `err.<CODE>`；建议 key 为 `hint.<CODE>`。
- 占位符使用具名花括号：`{n}`、`{name}`；插值参数必须具名。
- 翻译值中不要写 HTML。
- 不翻译参数名、函数名、文件名、方法名、软件名、单位与引用。

## 切换机制

界面一次性构建，并带有 `data-i18n` 属性。客户端保存由 CSV 生成的字典。切换时：

1. 字典更新所有 `[data-i18n]` 元素的文本。
2. 更新 `[data-i18n-placeholder]`、`[data-i18n-title]` 与
   `[data-i18n-aria-label]`。
3. `<html lang>` 切换为 `zh-CN` 或 `en`。
4. 客户端发送 `Shiny.setInputValue("lang", value)`。
5. 服务器更新 `lang`，刷新服务器渲染的帮助、表格、图、错误与选择项标签。
6. 输入、上传数据与结果保留在内存中。

服务器端文案使用 `tr(key, lang, ...)`。UI 代码使用 `tr_span(key, lang)`，使首次渲染与
后续客户端切换一致。

## 翻译流程

1. 在 CSV 中添加英文值。
2. 翻译为中文；不得为空。
3. 运行 `dev/build_i18n.R` 与 `dev/i18n_check.R`。
4. 若引入新术语，更新术语表。
5. 方法、错误、隐私、许可、引用等高危文案需领域审校。
6. 在 PR 描述中列出新增/修改的 key。

## 格式规则

- 小数点使用 `.`；科学计数为 `1.2e-3`。
- 数字与单位之间留空格：`10 Ma`。
- 文件名中的日期使用 UTC `YYYYMMDD-HHMMSS`。
- 中文标题不加句号；英文标题使用 Title Case。
- 错误文案：中文用“请…”，英文用“Please…”；避免责备语气。
- 高危文案不要未经审校直接机翻。

## 校验

`dev/i18n_check.R` 检查：

- CSV 列、key 唯一、值非空。
- 文档中列出的每个错误码都有 `err.*` 与 `hint.*`。
- `R/` 中使用的每个 `tr("...")` key 都存在。
- 浏览器字典包含所有 key。
- 中英文占位符一致（同名占位符集合相同）。

`tests/testthat/test-fct-i18n.R` 在单元测试中重复这些检查。

## 新增语言

1. 增加列（或新表），更新 `normalize_lang()`。
2. 扩展客户端字典构建器与语言选项。
3. 翻译帮助页与文档树。
4. 将新语言加入 QA 矩阵与截图目录。
5. 不要发布半翻译语言；在完成前回退到英文。

## 字体

界面使用系统字体。绘图通过 `sysfonts` 与 `showtext` 使用随包 Noto Sans SC，使 Linux
服务器在没有系统中日韩字体时也能显示中文。`www/fonts/NotoSansSC-Regular.ttf` 与
`www/fonts/OFL.txt` 必须一起保留。若对字体子集化，请根据当前翻译与文档重新生成，并
重新测试 PNG/PDF 导出。
